# Domain documentation

This repository has one domain context.

## Before exploration

Read the root GLOSSARY.md and ADRs relevant to the work in docs/adr/.
Follow the existing DESIGN.md and development-frontier reading order in AGENTS.md.
If a domain document is absent, proceed; domain-modeling creates it when needed.

## Vocabulary and decisions

Use glossary terms in specifications, issues, tests and implementation discussion.
Keep definitions in the glossary, accepted rules in DESIGN.md, implementation gates
in docs/development.md, rationale in ADRs and recovered facts in docs/evidence/.

Surface conflicts with ADRs explicitly. When an accepted decision changes,
update DESIGN.md and its frontier entry together and record consequential rationale.
