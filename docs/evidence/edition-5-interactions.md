# Robot interactions observed at runtime (#83)

Authority build `agame-bomb-it-5-zh-fix.swf` (sha256 `718c04c7…0408a2`). Runtime from the
patched reference player built on Linux (`tools/reference_player/build.sh` with
`reference-rides.patch`, Mesa lavapipe, probe sha256 `e75a7236…71f92b`) on 2026-10-29.
Static source from the FFDec 26.3.0 script export.

These six interactions were ported from source and listed as unobserved in the
[complete-game verification](../verification/complete-game-2026-10-21/README.md). The cases
are generated by `tools/reference_player/cases/interactions/make_cases.py`. The ride and catch
cases split the early step so the fixture can stop the AI (`step 62` with an `early` capture,
then `step 19`), and run Arcade mode so a Kill-mode AI does not interfere. Run outputs stay in
`.scratch/edition-5-research/reference-runs/` (not committed); the numbers the checks use are
in the fixtures named below.

## Conveyor belt ride

Case `belt-ride.json`: Candy Factory stage 1, seed 11, AI stopped, player repositioned to
(8,10) at counter 721 and left idle. Fixture `tests/fixtures/belt-ride.json` (180 frames).

- **Source.** `ConveyorBelt.robotMove` drives the robot with its own `HitMove` call, with the
  vertical pair swapped (`upAfoul` for a down belt). Each write goes through `xPos`, so it is
  truncated to twips at the board offset (183, 40).
- **Observed.** The robot moves 1 px per frame along the belt and its cell crossings fall on
  the twip positions.
- **Port.** Under the `original` profile, `belt.gd` pushes a robot through `Movement._afoul`
  on the double-precision pixel position. Carried bombs and pickups are truncated to twips.
  The replay matches all 180 frames to 1e-4 px, so the belt no longer drifts a tick.

## Toy hand push

Cases `toy-hand-01`–`04` (Birthday Party, seed 11): the robot at (12,7), boxes at (13,7)
and (14,7), pushed right twice.

- **Source.** `PushRobotCommand.moveFuc` steps whole pixels and checks the cell it is
  entering against `_preCheckXGrid`/`_preCheckYGrid`. Those fields are not cleared between
  pushes. When the entered cell is blocked, it snaps back to the cell before.
- **Observed.** The first push snaps straight back (no visible movement). The second push
  still holds the first push's checked cell (13,7), so it moves 360 → 375 → 390 and stops
  inside the box cell.
- **Port.** `_advance_push_original` keeps a persistent `push_check` and ports the stale
  cell literally. The check is `_toy_hand_pushes`.

## Crocodile bite

Cases `croc-01`, `croc-02`, `crocodile-bite.json` (Zoo).

- **Observed.** The cell turns dangerous when the closed count reaches 240. A robot on it is
  killed one frame after the mouth is fully open, and the mouth stays open for 60 frames.
- **Port.** These timings already matched `crocodile.gd`; no change.

## Horse jump

Case `horse-jump.json`: Birthday Party stage 2, seed 11, row 9, boxes at (4,9), (8,9) and
(9,9). A horse is picked up at (3,9) and right is pressed at counter 731. Fixture
`tests/fixtures/rides.json`, key `horse`.

- **Source.** A box in the leading cell (`_hitHandleArr`) runs `HorseProp.frog`. It aims at the
  cell after the box, with no bomb or box allowed there. It jumps at `drive_speed / 0.4` per
  frame, adds a ±1 px cross-axis correction, and stops with zero speed on the aim.
- **Port.** `_ride_hit_original` and `_advance_jump_original`. The `_rides` check matches the
  recording frame for frame.

## Dragon crash

Case `dragon-crash.json`: soft block at (3,1), box at (5,1), dragon `drive_speed` 1.28.
Fixture key `dragon`.

- **Source.** `DragonProp.crash` breaks a soft block ahead, scores 10, queues a drop and runs
  `RobotStopCommand(17)`. The stop does not clear the speed.
- **Observed.** The robot stops for 19 frames. The first step after the stop moves
  0.6·1.28 + 1.28 px, which shows the speed was kept.
- **Port.** The replica no longer zeroes the velocity on a crash. The robot is busy and
  protected for 19 steps.

## Pac-Man catch

Case `pac-man-catch.json` (Cinema, Pac-Man mode): the player walks one cell first (a pickup on
the current cell is not collected), takes the invincibility pickup and runs right into a
stopped ghost.

- **Observed.** The player's x is 435.1 on frame 860, which is inside the ghost's cell. The
  ghost dies on 861.
- **Reason.** The cell registers from the position before each step (`view.xN` lags), so the
  catch comes one step after the position enters the cell.
- **Port.** The replica's cell registration already lags. The `_pac_man_catch` check holds
  the one-step delay.

## Differences fixed

- The belt now uses twip arithmetic, where it used to use floats.
- The toy hand now has the stale checked cell.
- Horse jumps now use the source aim, speed and correction.
- A dragon crash now keeps the robot's speed.

Positions and speeds are now stored as doubles (`pixel_position`, `pixel_speed`) next to the
single-precision `Vector2`. Without them, twip truncation rounds the wrong way. All of these
changes apply only under `hit_move` (the replica host).
